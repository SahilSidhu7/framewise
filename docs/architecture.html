01 · System context

The big map

In plain words: there is one "engine" program that does all the work (AI, analysis, rendering). Everything else is a way of talking to it: the desktop app, the framewise command, n8n over HTTP, and AI agents over MCP. Nothing leaves your computer unless you add a webhook or give it a web link to download.

02 · Packages

Modules and what each one owns

In plain words: the code is split by job. core knows what a project is and how to change it safely (with undo). agent decides what to do. video and imaging actually make pixels. automation runs work in the background for other tools.
PackageKey filesResponsibility
coreproject.py, bus.py, video_commands.pyPydantic project model (tracks, clips, captions, grade). Every change is a named command on the CommandBus, so the app and the AI share one undo history.
agentvideo_planner.py, planner.py, highlights.py, reels.py, cleanup.py, options.py, llm.py, whisper.pyTurns a prompt plus style/output options into Edit DSL programs. Finds the best moments, cuts pauses and filler words, talks to the local LLM and whisper.
videovdsl.py, compose.py, text.py, captions.py, placement.py, reframe.py, audio.py, export.pyVideo Edit DSL parser/decompiler, layered compositor, caption drawing and placement, subject tracking for 9:16, audio mix with loudness, parallel segment export.
imagingops.py, render.py, recipes/Photo operations and looks; also the colour grade used on every video frame (baked into a 3D LUT by video/fastgrade.py).
automationjobs.py, recipes.py, keys.py, webhooks.py, watch.py, mcp.pyJob queue that survives restarts, seven recipes, hashed API keys with scopes, HMAC-signed webhooks with retries, watch folders, MCP server.
apiserver.py, video_routes.py, public_routes.pyDesktop routes (token-protected, loopback only) and the public /v1 job API mounted by framewise serve.
licence.pyone filePure-Python Ed25519 check of AIE1-… keys, 14-day trial, free-tier limits.
cli.pyone fileThe framewise command: serve, one-shot recipes, watch, keys, licence, mcp.

03 · Data

Project data model

In plain words: a project is a list of media files, some tracks with clips on them, captions on top, and one colour grade for the whole video. A clip never copies the media; it points at it with in/out times.
classDiagram
  class Project {
    name
    settings: ProjectSettings
    media: map id to MediaItem
    tracks: Track[]
    captions: Caption[]
    grade: EditOp[]
    duration()
    content_end()
  }
  class ProjectSettings {
    width, height, fps
    letterbox, fade_in, fade_out
    progress_bar: off|top|bottom
    end_card, end_card_seconds
  }
  class MediaItem { path, kind, width, height, duration, proxy_path }
  class Track { kind: video|overlay|audio; hidden; clips }
  class Clip {
    media_id, start, in_point, out_point, speed
    volume, fades, transition, motion
    transform x y scale rotation, opacity, blend
    keyframes: param to Keyframe[]
  }
  class Caption {
    start, end, text, style
    position, auto_position
    words: start time per word
    kind: caption|title
  }
  class EditOp { op, params }
  Project --> ProjectSettings
  Project --> "*" MediaItem
  Project --> "*" Track
  Track --> "*" Clip
  Clip ..> MediaItem : media_id
  Project --> "*" Caption
  Project --> "*" EditOp : grade

04 · Flow

Editing from a prompt (desktop app)

In plain words: you type what you want and pick a style and an output. The AI writes three small "edit programs" (Edit DSL). You preview them, pick one, and it becomes a single undo step. The AI never edits your project directly.
sequenceDiagram
  actor U as You
  participant UI as Desktop UI
  participant API as Engine API
  participant P as video_planner
  participant L as Local LLM
  participant B as CommandBus
  participant R as Renderer
  U->>UI: "fun travel recap" + style travel + TikTok
  UI->>API: POST /ai/video (prompt, style, output)
  API->>P: options pre-fill hints (aspect, pace, looks, captions)
  P->>L: grammar-constrained request
  L-->>P: Edit DSL text
  P-->>API: 3 variations (program + rationale)
  API-->>UI: variations
  U->>UI: preview, pick one
  UI->>API: POST /commands/video.apply_program
  API->>B: execute (one undo step)
  B-->>UI: websocket event, new revision
  UI->>API: GET preview frames
  API->>R: render_frame(project, t)
  R-->>UI: JPEG

05 · Flow

One long video in, reels out

In plain words: the engine listens to the video (whisper), finds the strongest moments, cuts out pauses and "um"s, follows the speaker so a wide shot becomes a vertical one, adds captions that light up word by word, and renders each reel.
flowchart TD
  A["Input video"] --> B["Import + probe
session.import_media"]
  B --> C["Analysis (cached by file)
scenes, loudness, motion, faces"]
  B --> D["Transcript
whisper.cpp, word timings"]
  C & D --> E["highlights.find_moments
LLM scores hooks + audio/visual peaks"]
  E --> F["cleanup.keep_ranges
drop silences and filler words"]
  F --> G["reframe.subject_track
camera path for 9:16"]
  G --> H["reels.reel_program
Edit DSL per moment"]
  H --> I["vdsl.apply_video_program
clips, look, captions, progress_bar, end_card"]
  I --> J["export_video"]
  J --> K["reel_1.mp4 ... + reels.json"]
  style E stroke-width:2px

Example program

aspect 9:16 · clip 1 27.72-39.80 x=0:0.42,8:0.19 · look vivid_pop s=0.75 · captions bold_pop · progress_bar top · end_card "Follow for part 2"

Why a program?

The same text is previewable, editable by hand, replayable, and is exactly what the future EditLM model will learn to write.

06 · Pipeline

How one frame is rendered

In plain words: for every output frame, layers are stacked bottom to top, the colour look is applied, fades and letterbox are added, then text goes on last so it stays sharp. Export splits the video into segments and renders them on several CPU threads.
flowchart LR
  T["time t"] --> CE{"t past content_end
and end card set?"}
  CE -- yes --> EC["End card
last frame blurred + darkened + text"]
  CE -- no --> L1["for each track bottom to top"]
  L1 --> L2["decode frame
(proxy in preview)"]
  L2 --> L3["transform, keyframes,
transition, opacity"]
  L3 --> L4["blend: normal / add /
screen / multiply / overlay"]
  L4 --> G["grade
256-cube LUT + grain"]
  G --> F["fade in/out, letterbox"]
  F --> C["captions
text.draw_text, word highlight"]
  C --> P["progress bar"]
  P --> O["uint8 RGB frame"]
  EC --> O

07 · Algorithm

Caption placement

In plain words: before export, the engine looks at a few frames under each caption, finds faces and any text already burned into the video (like a name title), and moves the caption to the spot that covers the least. Captions you placed by hand never move.
flowchart TD
  S["export_video starts"] --> CP["copy the project
(your undo history is untouched)"]
  CP --> LOOP["for each caption on Auto"]
  LOOP --> SAMP["render 1-4 frames under it
at 640 px, captions off"]
  SAMP --> FACE["faces: YuNet if installed,
else head cut from skin regions"]
  SAMP --> TXT["burned-in text: thin bright/dark strokes
in wide short bands"]
  FACE & TXT --> COST["cost per position =
3 x face overlap + 2 x text overlap
+ 0.12 per step from style's spot
+ 0.08 to change from last caption"]
  COST --> PICK["pick the cheapest:
center_low / bottom / high (9:16)
bottom / lower_third / top (16:9)"]
  PICK --> LOOP

08 · State machine

Automation jobs and webhooks

In plain words: n8n uploads a file, asks for a job, and either waits or gets a signed message when it is done. Jobs are saved to disk, so a restart does not lose the queue.
stateDiagram-v2
  [*] --> queued: POST /v1/jobs (202)
  queued --> running: worker picks it
  queued --> cancelled: cancel
  running --> done: outputs written
  running --> failed: recipe error
  running --> cancelled: cancel (stops at next checkpoint, stage "Cancelling")
  running --> failed: engine restarted (interrupted)
  done --> [*]: webhook job.done, files kept 7 days
  failed --> [*]: webhook job.failed
  cancelled --> [*]: webhook job.cancelled
PieceHow it works
UploadPUT /v1/files?name=talk.mp4 with the raw body, returns f_…. Inputs can also be URLs or (scope local) paths.
WaitGET /v1/jobs/{id}/wait?timeout=120 long-polls; n8n loops on it.
WebhookHeader X-Framewise-Signature: t=…,v1=HMAC_SHA256(secret, "t." + raw body); retried after 2, 10 and 30 s.
Keysaie_<id>_<secret>, stored as SHA-256 only; scopes jobs, local, admin; a key sees only its own jobs.

09 · Business rules

Free vs Pro, checked offline

In plain words: a Pro key is a signed note. The engine has the public half of the key and can check the signature without the internet. Only the seller's machine has the private half that makes keys.
flowchart LR
  SELL["Seller PC
tools/licence_issuer.py
private key in ~/.aieditor-issuer"] -- "AIE1-payload.signature" --> USER["Customer pastes key
framewise licence activate"]
  USER --> STORE["licence.json"]
  STORE --> CHECK{"Ed25519 verify
with built-in public key"}
  CHECK -- "valid, not expired" --> PRO["Pro / Studio"]
  CHECK -- "no key, trial running" --> TRIAL["Trial (14 days, once)"]
  CHECK -- "otherwise" --> FREE["Free"]

FREEAlways

Whole desktop editor. One-shot framewise commands and MCP with limits: 1 reel per video, 1 photo per job, no webhooks.

PROUnlocks

framewise serve (the /v1 API for n8n), watch folders, batches, webhooks, up to 10 reels per video. Blocked calls answer HTTP 402 with how to start a trial.

10 · Packaging

What the installer puts on your PC

In plain words: one 105 MB installer, no admin rights. The app window is a small Rust program; the engine is one frozen Python program it starts in the background. The same engine file is also the framewise command.

11 · Trust

Security boundaries

BoundaryRule
Desktop engineBinds 127.0.0.1 only, on a random port, with a fresh token per launch that never touches disk.
framewise serveLoopback by default; --allow-lan needed for a network address, with a warning. Never expose it to the internet directly.
API keysHashed at rest, constant-time compare, scopes; paths on your disk need the local scope.
WebhooksHMAC-SHA256 over timestamp + raw body; receivers reject anything older than 5 minutes.
LicenceOffline Ed25519 signature; the engine cannot make keys. Open-core: a determined user can patch Python, which is accepted.
